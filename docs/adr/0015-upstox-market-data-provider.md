# ADR 0015: Upstox as the market data provider, ISIN as the instrument identity

- Status: accepted
- Date: 2026-11-26
- Amends: ADR 0012 (sourcing) and ADR 0013 (instrument master source)

## Context
Market data must arrive without manual steps: no hand-downloaded files, no daily logins. Sources
were compared at their own pages on 2026-11-26:

| Source | Cost | Unattended | Notes |
|---|---|---|---|
| Upstox Analytics token | Free | Yes: read-only token valid 1 year | Daily candles from Jan 2000, minutes from Jan 2022 |
| EODHD | USD 19.99/month | Yes: API key | Personal-use plans; NSE coverage not confirmed |
| Dhan Data API | INR 499/month | Unclear | Token lifetime not found |
| Kite Connect | INR 500/month | No: token expires 6 AM daily | |
| Angel One SmartAPI | Free (2024 blog) | Unclear | Docs did not render |
| TrueData | On request | Login and password | Licence prohibits paper trading |

Upstox facts used here (developer docs, read 2026-11-26):
- Analytics token: "long-lived access token (1-year validity)", read-only (GET only), includes
  Historical Data, no static IP needed, free, one token per account, generated by the account
  holder in the developer console.
- Historical candles v3: `GET https://api.upstox.com/v3/historical-candle/{instrument_key}/{unit}/
  {interval}/{to_date}/{from_date}`; days back to January 2000, at most one decade per request;
  response `data.candles` = [timestamp with +05:30 offset, open, high, low, close, volume, OI].
- Rate limits for this API group: 50 per second, 500 per minute, 2000 per 30 minutes, per user.
- Instrument file `https://assets.upstox.com/market-quote/instruments/exchange/NSE.json.gz`:
  public (HTTP 200 without auth), refreshed daily around 6 AM, with ISIN, explicit series
  (`instrument_type`) and `instrument_key` = `NSE_EQ|<ISIN>` for equities.

Not verified: Upstox's terms for use of data obtained through the API (no terms page found);
whether the token carries a readable expiry. These are open items, see Consequences.

## Decision
- Upstox is the provider for end-of-day candles and for the instrument master. The Kite
  instruments loader is retired; one provider means one set of identifiers.
- ISIN is the canonical identity of an equity security. Provider identifiers (Upstox
  instrument_key today, others later) live in a provider-key mapping, not in the instrument row.
- Consumers depend on a provider-neutral `MarketDataProvider` interface. Adding Dhan, Kite or a
  licensed vendor later must not touch consumers.
- The Analytics token is a secret supplied through the environment (`UPSTOX_ANALYTICS_TOKEN`),
  never committed, never logged. A 401 from Upstox is treated as an expired or revoked token and
  raises an alert; the token's issue date is configured so the platform can warn 30 days before the
  one-year expiry.
- A client-side rate limiter stays well under the published limits.
- Ingestion runs as scheduled jobs with recorded runs, idempotent upserts, catch-up of missed
  trading days from the trading calendar, and validation through CandleValidator before storage.

- The instrument loader is provider-neutral and works over an `InstrumentFeed`. A fault in one row
  (an ISIN failing its check digit, a negative tick or lot size) rejects that row and is reported;
  more than a configured number of rejected rows, duplicates, the wrong exchange, too few rows or a
  large shrink fail the whole load.

Found on the first real load (2026-11-26): Upstox tick sizes are in paise (all 2,786 shares that
also appear in the Kite file were exactly 100 times Kite's rupee value); 9,910 of 9,911 ISINs pass
the ISO 6166 check digit, and the one that fails (a state government bond) was rejected.

## Consequences
The data layer runs unattended for a year at a time at no cost. The only human step is
regenerating the token yearly, with advance warning. Read Upstox's API and data terms in the
developer console before relying on the data beyond personal research; redistribution to other
users (Phase 3) will need a licence from a vendor or NSE. A second provider for cross-checking
(for example EODHD) can be added behind the same interface when a spend decision is made.
